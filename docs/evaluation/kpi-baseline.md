# KPI 基线与看板口径

> 版本：v0.1 / 2026-11-20
> 数据源：主 Agent 自己的 `wa_task_binding`、`wa_task_event`；不直连子 Agent 数据库。
> 接口：`GET /api/v1/admin/metrics/summary`（ADMIN）
> 页面：用户菜单 → 数据看板

## 1. 当前已实现的指标

| 指标 | 口径 | 用途 |
|---|---|---|
| 任务总数 | 时间范围内创建的 Task 数 | 规模 |
| 成功率 | `SUCCEEDED / total` | G1/G3 健康度 |
| 失败数 | `FAILED + REJECTED` | 质量 |
| 待确认 | `WAITING_CONFIRM` | 人工介入压力 |
| 平均耗时 | `finishedAt - startedAt` 均值 | 体验 |
| P95 耗时 | 同口径 95 分位 | 长尾 |
| 人工介入率 | `(APPROVED + REJECTED) / 有确认的写任务` | G6 |
| 能力分布 | 按 `capabilityId` 聚合调用/成功/失败 | 路由与能力治理 |
| Agent 分布 | 按 `agentKey` 聚合 | 子 Agent 健康度 |
| 工单漏斗 | 建单/派单/接单/解决/回访 成功次数 | G1 闭环（任务级，非唯一工单） |

## 4. 采集与展示原则

1. 主 Agent 只统计自己的任务与调用，不读取子 Agent 业务库；
2. 漏斗是“成功任务调用次数”，不是唯一工单数；需要唯一工单口径时由子 Agent 提供报表；
3. 人工介入率只统计有确认记录的写任务，避免把只读查询算进去；
4. 所有指标可按时间范围查询：`?from=...&to=...`；
5. 生产化后接入 Dashboard/告警，评测集纳入 CI 门禁。
