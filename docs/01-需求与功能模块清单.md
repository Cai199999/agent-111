## 1. 项目定位

`wuye-agent` 是一个**主 Agent / Orchestrator**：对外只提供一个对话框，对内通过统一 Agent 层接入多个领域子 Agent。

首期接入两个子 Agent：

| 子 Agent | agentKey | 领域 | 协议 | 现状 |
|---|---|---|---|---|
| Property Maintenance Agent | `property-maintenance` | 物业报修 / 工单 / 派单 / 现场 / 回访 / 知识 | `agent-task-v1` 0.7.0 | 文档齐全，服务未启动 |
| Contract Review Agent | `contract-review` | 合同审查 / 规则 / 知识 | `agent-task-v1` 0.6.0 | 文档齐全，服务未启动 |

主 Agent 的职责：

1. 统一身份、统一会话、统一对话框；
2. 发现子 Agent、缓存 Manifest、维护能力目录；
3. 把自然语言路由到正确的子 Agent 能力；
4. 统一任务状态、人工确认、事件时间线；
5. 统一审计、可观测与降级；
6. 为后续新增 Agent 预留标准接入层。

主 Agent **不负责**：

- 代替子 Agent 执行领域业务；
- 直连子 Agent 的 MySQL / Redis / MinIO / Milvus；
- 共享子 Agent 的聊天上下文或内部令牌；
- 跨领域的全局任务规划（首期只做单步路由与受控多步）。

## 2. 目标与非目标

### 2.1 目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 一个对话框同时完成物业与合同领域查询 | 同一会话内可查工单、合同规则、两域知识 |
| G2 | 写操作必须经过用户显式确认 | 子 Agent 返回 `WAITING_CONFIRM` 时，主 Agent 展示确认卡片，用户点击后执行 |
| G3 | 新增 Agent 不需要改主 Agent 核心代码 | 标准协议 Agent 通过注册 + Manifest 同步即可接入 |
| G4 | 子 Agent 故障可降级、可观测 | 健康检查、熔断、错误码、审计链路完整 |
| G5 | 资源与数据严格隔离 | 独立库/前缀/bucket，不直连子 Agent 存储 |

### 2.2 非目标（首期）

- 不做多租户运营后台（保留 `tenant_id` 字段，默认单租户）；
- 不做面向最终用户的自定义 Agent 创建器；
- 不做跨子 Agent 的复杂长流程编排（首期单步 + 少量多步）；
- 不做子 Agent 业务数据的二次建模；
- 不做移动端 App。

## 3. 用户角色与场景

| 角色 | 代码 | 说明 |
|---|---|---|
| 报修人 | `REPORTER` | 提交报修、查看自己的工单、补充现场信息 |
| 物业运营 | `OPERATOR` | 查工单、派单、接单、处理、回访 |
| 审核人 | `REVIEWER` | 工单验证、合同风险复核 |
| 管理员 | `ADMIN` | Agent 注册、能力开关、审计、指标 |
| 主 Agent 管理员 | `ADMIN` | 维护 Agent Registry、身份映射、凭据引用 |

典型场景：

1. 报修人问“我有哪些待处理工单？”→ 物业 `ticket.query`。
2. 运营说“把 GD20261119000107 派给 10002”→ 物业 `ticket.assign`，确认后执行。
3. 运营说“3 栋 2 单元水管漏水，帮我建单”→ 物业 `ticket.create`，槽位补全 + 确认。
4. 审核人问“合同审查有哪些规则？”→ 合同 `contract.rule.list`。
5. 审核人说“审查合同 10001 的 20001 版本”→ 合同 `contract.review`，异步任务 + 时间线。
6. 用户问“消防通道有什么规定？”→ 两域都有 `knowledge.search`，按规则/上下文消歧。
7. 用户上传现场照片 → 主 Agent 代理上传到物业子 Agent，再执行 `ticket.resolve`。
8. 管理员注册第三个 Agent → Manifest 同步、能力勾选、健康检查，无需改核心代码。

## 5. 功能模块清单

### F1 统一身份与会话

| 项 | 内容 |
|---|---|
| 功能 | 登录、JWT、当前用户、会话创建/列表/归档、身份映射 |
| 关键点 | 主 Agent 用户与子 Agent `actorId` 分离，通过 `wa_identity_mapping` 映射 |
| 验收 | 同一用户在两个子 Agent 下能映射到各自合法 Actor；无映射时拒绝写操作 |
| 阶段 | MVP |

### F2 单对话框交互

| 项 | 内容 |
|---|---|
| 功能 | 单会话聊天、流式输出、Markdown 渲染、路由标识、任务卡片、确认卡片 |
| 关键点 | SSE 流式；首字节 ≤ 1s；模型输出必须经过安全渲染 |
| 验收 | 一次提问可返回“路由 → 任务 → 结果”完整链路 |
| 阶段 | MVP |

### F3 Agent 注册与发现

| 项 | 内容 |
|---|---|
| 功能 | Agent Registry、Manifest 拉取与缓存、版本校验、健康检查、能力同步 |
| 关键点 | 支持 `property-v07` / `contract-v06` 两种方言；标准 Agent 走 `canonical-v1` |
| 验收 | 启动时自动拉取两个子 Agent Manifest；版本不兼容时拒绝接入并告警 |
| 阶段 | MVP |

### F4 能力目录与路由

| 项 | 内容 |
|---|---|
| 功能 | 能力命名空间、能力目录、规则路由、LLM 兜底、消歧、槽位补全 |
| 关键点 | `capabilityId` 全局唯一；LLM 只输出决策，不直接执行工具 |
| 验收 | `knowledge.search` 能区分 `property.` / `contract.`；低置信度必须追问 |
| 阶段 | MVP（只读能力） |

### F5 任务执行与状态

| 项 | 内容 |
|---|---|
| 功能 | Task 提交、幂等、同步/异步、超时、重试、状态归一化 |
| 关键点 | `clientTaskId` 全链路复用；主 Agent 自己掌握 deadline |
| 验收 | 同键重试不重复建单；子 Agent 超时后主 Agent 能给出明确失败 |
| 阶段 | MVP（SYNC 只读）→ P1（写 + ASYNC） |

### F6 人工确认

| 项 | 内容 |
|---|---|
| 功能 | 确认摘要、同意/拒绝、令牌服务端保管、过期处理、审计 |
| 关键点 | 浏览器永远拿不到子 Agent 的 `confirmationToken`；主 Agent 绝不自动确认 |
| 验收 | 未确认不落库；拒绝后任务终止；重复确认返回冲突 |
| 阶段 | P1 |

### F7 事件与任务时间线

| 项 | 内容 |
|---|---|
| 功能 | 子 Agent 事件归一化、SSE 推送、轮询降级、断线重连、`done` 处理 |
| 关键点 | 统一事件类型：`STATUS_CHANGED / PROGRESS / TOOL_CALL / ERROR / DONE` |
| 验收 | SSE 断开后能轮询补齐；终态只发一次 `done` |
| 阶段 | MVP（只读轮询/SSE）→ P1（异步时间线） |

### F8 附件代理上传

| 项 | 内容 |
|---|---|
| 功能 | 主 Agent 接收上传、存 MinIO、按需转发给子 Agent、下载鉴权 |
| 关键点 | 不暴露子 Agent 内部令牌；上传类型/大小/魔数校验 |
| 验收 | `ticket.resolve` 前可上传 `ONSITE` 照片；非处理人被拒绝 |
| 阶段 | P1 |

### F9 审计与可观测

| 项 | 内容 |
|---|---|
| 功能 | 路由决策、Agent 调用、任务状态、确认操作、错误码、耗时 |
| 关键点 | `traceId` + `correlationId` 贯穿；敏感字段脱敏 |
| 验收 | 任一用户提问可回溯到子 Agent 调用与确认记录 |
| 阶段 | MVP（基础日志）→ P1（审计查询） |

### F10 Agent 管理后台

| 项 | 内容 |
|---|---|
| 功能 | Agent 列表、注册、启停、Manifest 同步、能力开关、健康检查 |
| 关键点 | 仅 ADMIN；操作全部审计 |
| 验收 | 新增 Agent 不需要重启 Java 服务（热注册） |
| 阶段 | P1 |

### F11 扩展接入

| 项 | 内容 |
|---|---|
| 功能 | 标准 Agent Contract v1、`GenericV1Adapter`、方言 Adapter SPI |
| 关键点 | 标准 Agent 零代码接入；方言 Agent 只写一个 Adapter 类 |
| 验收 | 用 Mock Agent 验证“注册 → 同步 → 路由 → 任务”全链路 |
| 阶段 | P1 |

### F12 自定义 Agent（远期）

| 项 | 内容 |
|---|---|
| 功能 | 用户/管理员基于模板创建 Agent：提示词、能力白名单、知识库、配额、审批 |
| 关键点 | 不允许任意代码、任意 URL；沙箱 + 版本 + 评测 |

## 6. 关键业务流程

### 6.1 只读查询

```text
用户提问
  → 主 Agent 规则/LLM 路由
  → 选中 capabilityId（如 property.ticket.query）
  → 注入身份映射，提交子 Agent Task（SYNC）
  → 归一化结果
  → 生成自然语言回答 + 结构化卡片
```

### 6.2 写操作 + 确认

```text
用户提出写操作
  → 槽位补全（缺什么问什么）
  → 提交子 Agent Task
  → 子 Agent 返回 WAITING_CONFIRM（含 confirmationToken）
  → 主 Agent 把 token 存服务端，只把摘要推给浏览器
  → 用户点击“同意/拒绝”
  → 主 Agent 调用子 Agent confirm
  → 返回终态，写入审计
```

### 6.3 异步任务

```text
提交 ASYNC 任务
  → 主 Agent 返回 taskNo，前端展示任务卡片
  → 订阅子 Agent SSE / 轮询
  → 事件归一化后推送
  → 终态 done，生成结果摘要
```

### 6.4 歧义消解

```text
用户：“查一下知识库”
  → 命中两个 domain（property / contract）
  → 置信度不足
  → 主 Agent 追问：“要查物业知识库还是合同知识库？”
  → 用户选择后继续
```

## 7. 非功能需求

| 维度 | 要求 |
|---|---|
| 安全 | JWT 鉴权；内部令牌仅服务端；确认令牌不下发浏览器；Agent URL 白名单；审计不可篡改 |
| 性能 | 路由规则命中 P95 ≤ 200ms；LLM 路由 P95 ≤ 2.5s；SSE 首字节 ≤ 1s；同步只读任务 P95 ≤ 3s（不含子 Agent 自身耗时） |
| 可用性 | 单子 Agent 故障不影响另一域；连续 3 次健康检查失败标记 `DEGRADED`；支持熔断与重试 |
| 隔离 | 独立 MySQL 库 `wuye_agent_db`、Redis 前缀 `wuye_agent:`、MinIO bucket `wuye-agent`；不直连子 Agent 存储 |
| 兼容 | Manifest 版本校验；主版本不兼容拒绝接入；方言 Adapter 隔离 |
| 可观测 | 结构化日志、`traceId/correlationId`、Agent 调用日志、路由决策日志、审计日志 |
| 数据保留 | 聊天 180 天、审计 365 天、任务事件 90 天（可配置） |
| 可访问性 | 键盘可操作、确认卡片有明确风险提示、错误信息可读 |

## 8. MVP 验收标准

- [ ] 同一会话内可查物业工单、合同规则、两域知识；
- [ ] `knowledge.search` 歧义时必须追问，不自动猜域；
- [ ] 只读任务 SYNC 成功，结果有结构化卡片；
- [ ] 子 Agent 未启动时，主 Agent 返回明确降级提示，不崩溃；
- [ ] Manifest 可拉取、可缓存、版本可校验；
- [ ] 所有子 Agent 调用都带 `traceId/correlationId`；
- [ ] 主 Agent 未直连任何子 Agent 的数据库/对象存储；
- [ ] 浏览器网络请求中不出现子 Agent 内部令牌或确认令牌；
- [ ] 新 Agent 可通过注册 + Manifest 同步出现在能力目录（标准协议）。

## 9. 依赖与风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 两个子 Agent 当前均未启动 | 无法活体联调 | 先用 Mock Server + 文档契约开发 |
| 物业 Agent 默认端口 8400 与合同冲突 | 无法同时在线 | 物业改用 `AGENT_SERVICE_PORT`（候选 8402），先登记 |
| 合同 Agent 无委托令牌签发端点 | 写能力无法调用 | 推动子 Agent 增加签发端点，或提供 HMAC 规范 |
| 合同 Agent 无文件导入能力 | 单对话框只能审查已有合同 | 首期明确限制；P1 推动 `contract.import` |
| 物业异步队列为进程内线程池 | 重启丢任务 | 主 Agent 自己做超时/重试；推动持久化队列 |
| 身份 ID 体系不一致 | 越权或查不到数据 | 建立 `wa_identity_mapping`，逐 Agent 映射 |
| LLM 误路由 | 调错域/错能力 | 规则优先、置信度阈值、能力白名单、二次确认 |

## 10. 术语表

| 术语 | 含义 |
|---|---|
| 主 Agent | 本项目的单对话框编排服务 |
| 子 Agent | 物业/合同等领域 Agent，独立部署、独立数据 |
| Capability | 子 Agent 暴露的一个能力，如 `ticket.query` |
| capabilityId | 主 Agent 内部全局唯一能力 ID，如 `property.ticket.query` |
| Task | 一次能力调用，有独立状态机 |
| Confirmation | 写操作的人工确认，一次性令牌 |
| Dialect | 子 Agent 的协议方言，如 `property-v07` / `contract-v06` |
| Canonical v1 | 主 Agent 期望的新 Agent 标准协议 |
