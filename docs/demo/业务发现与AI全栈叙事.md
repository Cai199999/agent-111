# 面试主线：业务发现 × AI 全栈交付

> 一句话主张：
> **“我不是来演示一个物业系统，我是来演示一套方法：如何发现一个业务痛点，并用 AI 全栈在两天内把它做成可演示、可治理、可扩展的系统。”**

这份文档解决三个问题：

1. 面试时**先讲什么、后讲什么**；
2. 哪些 demo 瞬间能证明“业务发现”和“AI 全栈”；
3. 怎么把物业案例**迁移到苍穹数码的 GIS/遥感/自然资源业务**，而不显得生搬硬套。

---

## 一、10 分钟叙事结构

| 时间 | 内容 | 要让面试官记住的一句话 |
|---|---|---|
| 0–1 min | 业务发现：我观察到的三个断点 | “我不是先写代码，我是先找到值得做的流程。” |
| 1–3 min | 方案：一个对话框 + 三类角色 + 三条流程 | “AI 只做它擅长的部分，写操作必须人确认。” |
| 3–6 min | Demo：三个证据时刻 | “从一句话到可执行任务，再到可治理的闭环。” |
| 6–8 min | 架构与治理：Java BFF + Python 推理 + 审计/权限/人工队列 | “这不是 demo 玩具，是按生产契约做的原型。” |
| 8–10 min | AI 协作方式 + 苍穹场景机会地图 | “这套方法可以直接复用到你们的业务。” |

**不要**一上来讲技术栈。先讲业务断点，再讲方案，最后用技术证明。

## 二、业务发现：怎么讲才像“真的发现过业务”

### 2.1 发现方法（30 秒讲清）

> “我先跟了三个角色：报修用户、维修工、物业管理员；抽了 30 条历史工单；把失败案例按‘信息不全、派单错误、进度不透明、合同审查靠人’分类。最后选了一个高频、规则可描述、错误成本可控、且一定有人工兜底的场景做 MVP。”

这套方法可以复用到任何行业：

1. **跟岗/访谈**：看真实的人怎么干活，不看需求文档。
2. **任务抽样**：收集 20–30 个真实任务，标注耗时、输入、规则、异常。
3. **失败分析**：哪一步最容易返工、扯皮、卡住。
4. **AI 适配度打分**：高频 × 规则清晰 × 数据可得 × 错误成本可控 × 有人工兜底。
5. **定义指标**：单任务耗时、一次解决率、人工介入率、单任务成本。

### 2.2 本项目的三个业务断点

| 断点 | 现状 | Agent 的切入点 |
|---|---|---|
| 报修入口分散、信息不全 | 电话/微信/口头，位置、类型、优先级经常缺 | 一个对话框自然语言建单，LLM 补参 + 枚举映射 |
| 派单靠人、进度不透明 | 管理员手工派，用户反复问 | 路由到派单能力，任务时间线 + SSE/轮询 |
| 合同审查靠法务 | 规则散落、初审耗时 | 异步合同审查子 Agent，风险点分级，人工复核 |

**关键话术：**
> “我没有把 AI 塞进所有环节。查询、补参、初筛可以 AI 主导；写操作、高风险合同结论必须人确认。AI 的价值是缩短‘信息整理’和‘流程流转’，不是替代责任人。”

### 2.3 不要假装懂苍穹的业务

正确姿态：

> “我没在自然资源行业干过，所以我不会假装懂你们的流程。但我有一套快速发现业务的方法：给我两周，我跟 3 个角色、抽 30 个任务，先找出一个高频、低风险、数据可得的切口做纵向切片。下面是我基于公开信息做的三个假设场景，想听听哪个最接近你们的现实。”

这句话同时展示：**业务发现能力 + 谦逊 + 可执行计划**。

## 三、方案：把“AI 全栈”讲成能力，而不是工具

### 3.1 角色与流程

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| 普通用户 | 报修、查自己的工单、看知识 | 不能派单、不能看别人工单、不能审合同 |
| 维修工 | 接单、处理、解决、回访 | 不能建单、不能审合同 |
| 管理员 | 全部能力、合同审查、看板、审计、人工队列 | 写操作仍需确认 |

**Before / After：**

```text
Before: 用户打电话 -> 管理员手记 -> 微信群派单 -> 用户反复问 -> Excel 统计
After:  用户一句话 -> Agent 补参/路由 -> 管理员确认 -> 任务时间线 -> 看板/审计自动沉淀
```

### 3.2 AI 做什么、不做什么

| 环节 | 谁主导 | 为什么 |
|---|---|---|
| 意图识别、参数抽取、枚举映射 | LLM | 自然语言多样性，规则难穷举 |
| 能力选择、计划拆解 | LLM + 白名单 | LLM 只输出 JSON，不直接调工具 |
| 必填校验、参数修正 | 后端 schema + 子 Agent 二次校验 | 防幻觉、防编造 ID |
| 写操作 | 人 | 风险、责任、合规 |
| 失败/拒绝/待确认 | 人工介入队列 |  AI 不能兜底所有异常 |
| 审计、成本、成功率 | 系统 | 可运营、可追责 |

### 3.3 业务指标（面试时主动说）

- 建单耗时：从“电话 3–5 分钟 + 信息补录”降到“一句话 + 一次确认”
- 一次解决率：工单信息完整度提升，减少返工
- 人工介入率：衡量自动化边界，而不是越低越好
- 单任务 LLM 成本：按 token 计量，证明 AI 不是黑盒开销
- 合同初审时长：异步任务 + 风险分级，人工只看法务判断

> 注意：这些是**演示假设/目标指标**，不要说成“已生产验证”。真实验证需要跟岗和 A/B。

## 四、Demo 的三个“证据时刻”

### 证据 1：自然语言 → 结构化参数 → 人工确认

输入：

> 1栋大堂的灯不亮了

面试官看到：

- LLM 路由徽标：`property.ticket.create`、置信度、路由原因；
- “灯不亮”自动映射 `LIGHTING`，位置抽取为“1栋大堂”；
- 高风险确认卡片；
- 确认后 `SUCCEEDED`，返回工单号。

**证明：** 业务理解 + 参数补全 + 安全边界。不是“聊天机器人”，是“能办事的 Agent”。

### 证据 2：异步合同审查 + 任务时间线

输入：

> 审查合同 HT-2026-001

面试官看到：

- 任务先 `PENDING`，事件时间线推进；
- 约 1.5 秒后 `SUCCEEDED`，3 个风险点、`overall=FAIL`；
- 可展开 `STATUS_CHANGED / PROGRESS / TOOL_CALL / DONE`。

**证明：** 复杂流程编排、异步任务、事件驱动、可观测。

### 证据 3：看板 + 人工介入 + 审计

操作：

- 打开数据看板：业务价值（自动化完成率、预计节省工时、单任务 LLM 成本）+ 运行指标（成功率、待确认、人工介入率、token/成本、工单漏斗）；
- 拒绝一次高风险操作 → 自动进入人工介入队列；
- 打开审计日志：登录、提交、确认、取消都有记录。

**证明：** 可运营、可治理、可追责。这是企业/政务客户最在意的部分。

## 五、AI 全栈交付：用证据说话

### 5.1 项目证据（面试时可展示）

| 维度 | 证据 |
|---|---|
| 规模 | 103 个 Java 文件、约 1.1 万行核心代码（Java/Python/JS/HTML/CSS） |
| 迭代 | 34 个提交，集中在 2026-11-20 ～ 11-21 |
| 后端 | Java 21 + Spring Boot 3.5 + Spring JDBC + Flyway + JWT/RBAC |
| AI | Python FastAPI + DeepSeek 路由/解释/摘要/参数修正 |
| 前端 | 原生 HTML/CSS/JS + SSE，单对话框 + 任务卡片 |
| 数据 | MySQL `wuye_agent_db`，9 个 Flyway 迁移 |
| 测试 | Java 35 + Python 11 + 端到端 16 项链路冒烟 |
| 交付 | 一键启动 `scripts/start-demo.sh`、CI 门禁、备份脚本 |
| 文档 | 10 份设计/契约/演示文档，含 Agent 接入规范 |
| 治理 | RBAC、审计、限流、确认令牌、人工介入、成本看板 |

> 这些数字的意义不是“代码多”，而是：**在很短时间内，用 AI 完成了从需求、设计、契约、实现、测试到可演示交付的完整闭环。**

### 5.2 我怎么和 AI 协作（面试重点）

不要说“我用 AI 写代码”，要说“我怎么指挥 AI”：

1. **Spec-first**：先写业务 brief、角色、流程、验收标准，再让 AI 写代码。
2. **Contract-first**：先定子 Agent 协议、capability schema、错误码，再实现 Adapter。
3. **纵向切片**：一次只打通一条端到端链路，不铺大摊子。
4. **测试门禁**：每个切片必须有测试/冒烟，失败不进入下一轮。
5. **小步提交**：34 个提交，每个提交可回滚、可解释。
6. **记忆与边界**：`docs/memory/` 记录决策；明确禁止跨项目改动、共享中间件只读。
7. **人工验收**：AI 可以写，但架构取舍、安全边界、最终代码审查由我负责。

**一句话：**
> “AI 负责速度和覆盖面，我负责边界、契约、验收和线上治理。没有测试和契约的 AI 代码，我不敢上线。”

### 5.3 不要夸大

主动说边界：

- 子 Agent 目前是 mock，真实 8402/8400 还没活体联调；
- 没接 Redis/MinIO，确认令牌在进程内；
- 没做生产压测、没接 Prometheus/OpenTelemetry；
- 没接真实 GIS 引擎/空间索引。

> “这是一个按生产契约做的原型，不是生产系统。它的价值是证明方法论和工程能力，而不是证明我已经上线过。”

## 六、苍穹数码场景机会地图

> 用法：面试时拿出这一页，说“这是我基于公开信息做的三个假设，想请教哪个最接近你们的现实”。不要声称已经调研过他们内部。

| 场景 | 角色 | 痛点 | Agent 切入点 | 需要的数据 | 成功指标 | 风险/边界 |
|---|---|---|---|---|---|---|
| **不动产登记/权籍资料预审** | 窗口人员、审核员 | 材料清单靠经验、缺件反复退、政策口径不一 | 材料清单生成、缺件检查、政策知识问答（带出处）、预审意见草稿 | 办事指南、材料模板、政策法规、历史退件 | 一次通过率、退件率、单件耗时 | 结论必须人工签批；政策版本要可追溯 |
| **遥感变化检测复核** | 解译员、复核员 | 图斑多、误报多、复核靠人盯屏 | 变化图斑分级、相似案例检索、复核任务派发、报告草稿 | 影像、图斑、历史复核结论、地类规则 | 复核效率、误报率、漏报率 | 模型结论只做辅助；复核留痕；影像不出域 |
| **自然资源巡查/执法工单闭环** | 巡查员、执法人员 | 发现靠人、派发靠群、证据散、闭环难 | 语音/照片报事、自动补参、派单、时限提醒、证据链归档 | 网格、地块、人员、历史工单、执法依据 | 处置时长、按时办结率、复发率 | 写操作人工确认；执法结论人工负责 |
| **测绘/服务合同合规审查** | 项目经理、法务、财务 | 合同条款多、付款节点/成果验收易漏 | 条款抽取、风险分级、付款节点核对、审查报告 | 合同文本、示范条款、历史风险点 | 初审时长、风险召回率 | 法务终审；合同不出域 |

**收尾话术：**
> “这四个场景的共同点是：高频、规则可描述、数据可得、错误成本可控、必须有人工兜底——正好是我这套主 Agent + 子 Agent + 人工确认架构擅长的。换掉子 Agent 和主数据，底座不用改。”

## 七、如果入职：30/60/90 天计划

| 阶段 | 目标 | 产出 |
|---|---|---|
| 0–30 天 | 跟岗 3 个角色、抽 30 个任务、选 1 个切口 | 业务发现报告、指标基线、MVP 范围 |
| 30–60 天 | 打通 1 条真实系统链路 | 纵向切片、权限/审计、试点用户反馈 |
| 60–90 天 | 复制到 2–3 个 Agent，建立运营机制 | 质量/成本看板、人工介入 SOP、推广计划 |

**面试时主动给计划，比等对方问“你来了想做什么”更加分。**

## 八、高频追问（业务 + AI + 工程）

**Q1：你怎么发现这个业务的？**
> 跟岗、任务抽样、失败分析，不是先写代码。选场景的标准是高频、规则清晰、数据可得、错误成本可控、有人工兜底。

**Q2：AI 写的代码怎么保证质量？**
> 契约先行 + 测试门禁 + 小步提交 + 人工审查 + 线上可观测。这个项目 35 个 Java 测试、11 个 Python 测试、16 项端到端冒烟，不是“生成完就完”。

**Q3：为什么先做物业？是不是只会做这个？**
> 物业有清晰的角色、高频任务、低错误成本，适合验证“主 Agent + 子 Agent + 人工确认”这套底座。我要证明的是方法论，不是物业行业经验。

**Q4：让你做 GIS/遥感，第一周做什么？**
> 不急着写代码。先跟 3 个角色、抽 30 个任务、确认数据能否出域、找一个高频低风险切口；第二周做一条只读 Agent 纵向切片，比如“图斑相似案例检索 + 复核意见草稿”。

**Q5：数据安全/私有化怎么办？**
> 支持私有化部署；模型网关可换本地/专有模型；数据不出域；RBAC + 审计 + 确认令牌；敏感字段脱敏；子 Agent 数据物理隔离。

**Q6：AI 全栈是不是只会 prompt？**
> 架构取舍、契约设计、权限模型、失败处理、测试策略都是我定的。AI 加速实现，但不替代判断。你可以随便挑一个模块问实现细节。

**Q7：这个项目最大的不足？**
> 子 Agent 是 mock、没接 Redis/MinIO、没压测、没接真实 GIS 引擎。下一步先做真实子 Agent 活体联调，再补确认令牌持久化、事件 SSE、OpenTelemetry。

## 十一、不要说的话

- ❌ “这个系统已经很完整了。” → 它是原型，主动讲边界。
- ❌ “代码都是 AI 写的。” → 要讲你怎么指挥、怎么验收。
- ❌ “物业和 GIS 差不多。” → 尊重行业差异，讲方法迁移。
- ❌ “我什么都能做。” → 聚焦业务发现 + 全栈交付 + 治理。
- ❌ 一上来讲 Spring Boot / FastAPI。 → 先讲业务断点，技术是证据。

## 十二、30 秒收尾话术

> “我做的事情可以概括成三步：先跟业务，找到高频、规则清晰、错误成本可控的断点；再用主 Agent + 子 Agent 把流程做成可确认、可审计、可降级的闭环；最后用 AI 全栈快速交付、用测试和治理保证它敢给人用。物业只是我的验证场景，这套方法可以直接搬到不动产、巡查、遥感复核这些业务上。”
