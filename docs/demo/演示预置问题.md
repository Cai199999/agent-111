# 演示预置问题与“面试官追问”清单

> 原则：下面所有输入都走**真实能力**：
> - 业务问题 → 真实子 Agent / Mock 数据；
> - 平台问题 → `platform.catalog / platform.a2a / platform.memory` 读取真实注册表/记忆；
> - 企业 Agent → 真实 HTTP Agent Card + task 契约，不是聊天框里写死的答案。
>
> Mock 数据会明确标注“Mock/示例”，不冒充生产数据。

---

## 一、开场与主链路（照着输入）

> 不需要输入编码。主 Agent 会先按名称/描述做只读检索：
> 唯一命中就继续，多个候选才追问；编码只是兜底，不是入口。

### 1. 平台有什么

```text
现在平台上有哪些 Agent？各自能做什么？
```

真实返回：

- `platform.catalog` 读取注册表；
- 输出当前 3 个 Agent、能力数、协议版本、可见性；
- 不会返回固定文案。

### 2. 工单查询

```text
现在还有哪些没处理的工单？
```

### 3. 建单 + 人工确认

```text
1栋大堂的灯不亮了，帮我报修
```

预期：映射 `LIGHTING` → 高风险确认卡 → 确认后成功。

### 4. 派单 / 关闭

```text
把3栋2单元水管漏水那个工单派给张师傅
```

```text
把1栋大堂照明故障那个工单关掉
```

预期：系统先按描述查工单，唯一命中后自动映射 `ticketNo` 和“张师傅 → 10002”，再弹确认卡。

### 5. 合同审查

```text
帮我审一下物业服务合同
```

预期：先 `contract.resolve` 按名称解析出 `contractId`，再异步审查，`PENDING → SUCCEEDED`，3 个风险点。

### 6. 时空资产 Agent（可扩展性证明）

```text
江北新区 A-01 那个商业地块现在什么状态？
```

```text
最近有没有比较紧急的遥感变化图斑？
```

```text
安排人去江北 A-01 地块做一次变化图斑复核
```

预期：系统按名称/区域检索地块，唯一命中 `P-2026-001` 后自动带入巡查任务，不需要用户输入地块编码。

### 7. 自修复：不知道就问

```text
报修：花园的喷泉坏了
```

预期：不猜类型，追问“照明、给排水、电梯、安防、保洁、其他？”。

### 8. 自然语言 → 内部 ID 的解析

| 用户说 | 主 Agent 实际做 |
|---|---|
| “3栋2单元水管漏水那个工单” | 先 `property.ticket.query(keyword=...)`，唯一命中 `GD20261119000107`，再派单 |
| “张师傅” | 通过 `optionCatalog.workers` 映射到 `10002` |
| “物业服务合同” | 先 `contract.resolve(query=...)` 拿到 `contractId`，再审查 |
| “江北 A-01 地块” | 先 `gis.parcel.query(keyword=...)` 唯一命中 `P-2026-001`，再创建巡查 |
| “比较紧急的图斑” | 映射 `level=HIGH`，只返回高等级图斑 |

**面试话术：**
> “正常用户不会输入编码。主 Agent 的职责就是把自然语言里的名称/描述解析成内部 ID：先查、唯一命中就继续、多个候选才追问。编码只是兜底，不是入口。”

## 二、安装完整 Agent（巡检报告）

### 1. 安装

侧边栏「Agent 状态」→ `＋` →「安装巡检报告 Agent」。

### 2. 查询

```text
查询巡检报告
```

### 3. 生成（确认 + 异步 + 事件）

```text
生成今天的巡检报告
```

预期：

- 确认卡：日报 / 全部区域 / 今天；
- 确认后 `PENDING → RUNNING → SUCCEEDED`；
- 返回 `IR-2026-001`。

### 4. 导出

```text
导出巡检报告
```

## 三、安装企业 Agent（真实 HTTP 契约）

侧边栏「Agent 状态」→ `＋`：

- 「安装政策法规问答 Agent」
- 「安装客服工单 Agent」

也可手动输入 URL：

```text
http://127.0.0.1:8600/demo-agents/policy
http://127.0.0.1:8600/demo-agents/customer
```

### 政策法规问答 Agent

```text
查询政策：耕地保护
```

真实返回：

- `policy.qa.ask`；
- 引用《土地管理法》《永久基本农田保护条例》；
- `memoryUsed: true`（主 Agent 注入了会话摘要/画像）。

### 政策文件审查（写操作确认）

```text
审查政策文件：耕地保护实施细则
```

### 客服工单 Agent

```text
查询客服工单
```

```text
创建一个客服工单：客户反馈缴费记录查不到
```

预期：写操作弹确认卡。

## 四、面试官追问时的“真实自省”输入

> 这些不是固定答案，输入后会读取真实注册表/记忆/协议状态。

### 1. 平台有多少 Agent？

```text
现在平台上有哪些 Agent？各自能做什么？
```

返回：真实 Agent 列表、能力数、协议版本；安装新 Agent 后数量会变。

### 2. A2A 支持到什么程度？

```text
A2A 现在支持什么？
```

返回：

- `protocol=agent-task-v1`；
- `a2aCompatibility=discovery-only`；
- `agentCard=true`；
- `jsonRpc=false`、`pushNotifications=false`；
- SSE/人工确认/取消=true；
- 当前 Agent 数、能力数、动态 Agent 列表。

### 3. 记忆系统有什么？

```text
现在记忆里有什么？
```

返回：

- 当前会话摘要；
- 全局用户画像（偏好、置信度、来源会话）；
- 不是写死的“我们有记忆”。

### 4. 新装的 Agent 记得我吗？

先安装政策问答 Agent，再输入：

```text
查询政策：耕地保护
```

返回里会有：

```json
"memoryUsed": true,
"memoryHint": "已结合主 Agent 注入的会话摘要/用户画像"
```

### 5. 没安装的能力会不会报错？

在未安装政策 Agent 时输入：

```text
查询政策：耕地保护
```

返回：

> “这个能力还没有安装或暂不可用。可以到侧边栏「Agent 状态」安装对应 Agent 后再试。”

不是 500，也不是技术堆栈。

### 6. 现在装了哪些动态 Agent？

```text
现在平台上有哪些 Agent？
```

安装后返回的 `agents` 会包含 `policy-qa-agent` / `inspection-agent`，`platform.a2a` 的 `dynamicAgents` 也会列出。

## 五、哪些问题不要输入聊天框

下面这些建议**口头回答**，不要让业务 Agent 硬答：

- “你们能保证生产可用吗？”
- “为什么用 Java + Python？”
- “怎么防止 LLM 幻觉？”
- “你们和 Google A2A 什么关系？”
- “如果给你一个 GIS 场景，你怎么做？”

原因：这些是架构/方法论问题，聊天框里没有对应业务能力；硬答容易变成固定话术。正确做法是：

1. 用 `platform.catalog` / `platform.a2a` 展示真实数据；
2. 用 A2A 能力面板展示 Agent Card；
3. 口头讲架构边界和演进路线。

## 六、真实企业 Agent 模型清单

| Agent | 安装 URL | 能力 | 记忆 |
|---|---|---|---|
| 政策法规问答 Agent | `/demo-agents/policy` | 政策问答、政策文件审查 | 主 Agent 注入 `_memory` |
| 客服工单 Agent | `/demo-agents/customer` | 客服工单查询、创建 | 主 Agent 注入 `_memory` |
| 巡检报告 Agent | 模板安装 | 查询、计划、异步生成、异步导出 | 主 Agent 注入 `_memory` |

这些 Agent 都是：

- 真实 HTTP Canonical v1 契约；
- 有 Agent Card、health/ready、tasks/confirm/cancel/events；
- 不执行任意代码；
- 记忆统一由主 Agent 层注入，子 Agent 不各自维护记忆库。

---

## 七、建议演示顺序（8–10 分钟）

1. 登录，展示 3 个 Agent（30 秒）
2. `现在平台上有哪些 Agent？`（30 秒，真实注册表）
3. 工单查询 + 建单确认（1.5 分钟）
4. 合同审查（1 分钟）
5. 时空资产：地块/图斑/巡查（1 分钟）
6. `＋` 安装巡检 Agent → 查询/生成/导出（1.5 分钟）
7. `＋` 安装政策 Agent → 政策问答（记忆 `memoryUsed`）（1 分钟）
8. `A2A 现在支持什么？` + Agent Card 面板（1 分钟）
9. 看板/审计/人工队列（1 分钟）
10. 收尾：可扩展性证明 vs 完整 Agent（30 秒）

## 八、兜底

- LLM 不可用：`DEMO_AI=0 bash scripts/start-demo.sh`；
- 规则路由覆盖：工单、合同、GIS、巡检、政策、客服、平台自省；
- 动态 Agent 未安装：友好提示，不报错；
- 外部 URL 不可达：安装接口返回明确错误，不影响已有 Agent；
- 数据脏：`bash scripts/reset-demo-data.sh --yes` 后重跑 smoke。
