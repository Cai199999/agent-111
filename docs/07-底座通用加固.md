# 07 底座通用加固

> 版本：v0.1 / 2026-11-24
> 范围：H1 Agent 注册持久化、H2 Manifest 表单聚合、H3 Agent Card 权限声明。
> 边界：只做通用能力，不包含任何具体业务 Agent 的字段、枚举、规则或文案。

---

## 0. 背景

底座支持运行时安装外部 Agent，但动态注册是内存态，重启丢失；个人中心只渲染物业 Agent 的
`forms.personalInfo`；外部 Agent 的能力默认仅管理员可用。这三项是任何外部 Agent 都会遇到的
通用问题，因此作为底座通用加固处理，完成后重新冻结。

设计依据与完整验收见 `flow-agent` 项目的 `docs/08-底座通用加固方案.md`。

## 2. H1 · Agent 注册持久化

### 2.1 表

`apps/java-bff/src/main/resources/db/migration/V11__agent_registry.sql`

关键列：

- `agent_key`（唯一）、`kind`（HTTP/TEMPLATE）、`template_key`
- `descriptor_json`、`base_url`、`internal_token_cipher`
- `audience/actor_id/roles/tenant_id/use_delegation`
- `health_path/ready_path/manifest_path`
- `status`（ACTIVE/REMOVED）、`installed_by`、`installed_at`、`updated_at`

### 2.2 代码

```
agent/install/
  AgentRegistryEntry.java           # 持久化记录
  AgentRegistryStore.java           # 存储接口
  InMemoryAgentRegistryStore.java   # 默认/测试
  MySqlAgentRegistryStore.java      # mysql profile；AES-GCM 加密令牌
  AgentRegistryBootstrap.java       # ApplicationReadyEvent 启动加载
  AgentInstallService.java          # 安装写库、卸载标记、失败回滚
```

### 2.3 行为

- 安装成功后写注册表；写库失败回滚内存注册，返回错误，避免“内存有、库里没有”。
- 卸载时先注销内存，再标记注册表 `REMOVED`；标记失败记录错误。
- 启动时加载 `ACTIVE` 记录：
  - HTTP Agent：反序列化描述、解密令牌、重建 `DynamicHttpAgentAdapter`、注册；
  - 模板 Agent：按 `template_key` 重新注册；
  - 单条损坏/解密失败：跳过并告警，不阻塞其他 Agent；
  - 不主动探活，避免子 Agent 不可达拖慢启动；健康由管理端按需查询。
- 开关：`wuye.agent.registry.load-on-startup`（默认 true）。

### 2.4 测试

- `AgentInstallServiceTest`：安装写注册表、卸载标记 REMOVED。
- `AgentRegistryBootstrapTest`：从注册表恢复 HTTP Agent；关闭开关时不恢复。
- 全量 Java 测试：68/68 通过（2026-11-24）。

### 2.5 未验证 / 待办

- MySQL 真实迁移与重启恢复尚未在共享库执行；计划在 H4 回归前用 `wuye_agent_db` 验证。
- 安装审批/完整审计（G-07）不在 H1 范围。

## 3. H2 · Manifest 表单聚合

### 3.1 实现

- `AgentAdapter` 增加默认 `manifest()`（默认空）；`AbstractHttpAdapter` 拉取
  `endpoint.manifestPath`（默认 `/agent/v1/manifest`），2 秒短超时，失败返回空。
- `AgentManifestService` 聚合：
  - 物业：沿用 `PropertyManifestService`（含 mock/fallback）；
  - 运行时安装的 Agent：遍历 `DynamicAgentRegistry`，通过 `adapter.manifest()` 拉取；
  - 成功结果缓存 5 分钟；无 `forms.personalInfo` 的 Agent 自动跳过。
- 新增接口（旧接口保留）：
  - `GET /api/v1/profile/forms` → `{sections:[...]}`；
  - `GET /api/v1/profile/forms/{agentKey}` → 段定义 + 可选 `data`（调用 `getCapability`）；
  - `POST /api/v1/profile/forms/{agentKey}` → 调用 `updateCapability` 提交。
- 权限：按段的 `getCapability`/`updateCapability` 过滤；ADMIN 全量；未声明的段只读。
- 前端：个人中心新增 `#profileSections`；只渲染非物业段（物业仍走原表单），单段失败不影响其他段。

### 3.2 测试

- `AgentManifestServiceTest`：聚合、按 key 查询、缓存、无表单跳过（3 项）。
- `PrototypeSmokeTest` 新增 `/api/v1/profile/forms` 回归（物业段对 ADMIN 与普通用户均可见）。
- 全量 Java：72/72 通过（2026-11-24）。

### 3.3 边界

- 内置合同 Agent 暂不参与聚合；只有运行时安装且声明 Manifest 的 Agent 会出现在扩展段。
- 如果未来需要内置 Agent 也聚合，可显式加入白名单，不影响现有实现。
- 旧接口 `/api/v1/profile/form` 与 `POST /api/v1/profile` 行为不变。

## 4. H3 · Agent Card 权限声明

### 4.1 实现

- 迁移 `V12__agent_permission_source.sql`：`wa_permission` 增加 `source`（默认 `BUILTIN`）与索引。
- 新增 `DynamicPermissionService` 接口：
  - `NoopDynamicPermissionService`（`!mysql`）：不持久化，保持“动态 Agent 仅 ADMIN”的旧行为；
  - `MySqlDynamicPermissionService`（`mysql`）：真实写入/撤销，带事务与审计。
- Card 契约：

```json
{
  "permissions": {
    "agentUse": "agent:oa-entry-agent:use",
    "agentUseRoles": ["BASE", "WORKER", "ADMIN"],
    "capabilities": {
      "oa.request.draft": ["BASE", "WORKER", "ADMIN"],
      "oa.workflow.act": ["WORKER", "ADMIN"]
    }
  }
}
```

- 规则：
  - 能力权限码 = `capability:<capabilityId>`；
  - `agentUse` 未给角色时，默认取所有能力角色的并集；`agentUseRoles` 可覆盖；
  - 未知角色 → 400，安装失败；
  - 权限码与内置或其他 Agent 冲突 → 409，安装失败；
  - 权限来源 = `AGENT:<agentKey>`；
  - 安装写权限失败 → 回滚内存注册 + 注册表标记 REMOVED；
  - 卸载只删除该来源的权限与角色关联；
  - 安装/卸载写审计（`AGENT_PERMISSIONS_GRANT` / `AGENT_PERMISSIONS_REVOKE`）。

### 4.2 测试

- `DynamicPermissionParseTest`：能力解析、角色并集、`agentUseRoles` 覆盖、空声明、非法 `agentUse`、空角色跳过（5 项）。
- `AgentInstallServiceTest`：安装调用 grant、卸载调用 revoke。
- 全量 Java：77/77 通过（2026-11-24）。

### 4.3 未验证

- MySQL 真实写入/撤销与角色生效尚未在共享 `wuye_agent_db` 执行；计划 H4 回归前验证。
- 角色透传（G-02/G-03）仍不在范围；OA 侧继续忽略 `X-Actor-Roles`，按本地绑定派生权限。
